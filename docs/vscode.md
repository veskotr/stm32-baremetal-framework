# VS Code Workflow

`HSS STM32 framework` can generate VS Code tasks and launch configuration for firmware targets.

The generated workflow expects:

- CMake
- `arm-none-eabi-gcc`
- `arm-none-eabi-gdb`
- OpenOCD
- the VS Code Cortex-Debug extension

## Generate Files

The recommended project-level setup is to call `hss_generate_vscode()` after creating a firmware target:

```cmake
hss_add_firmware(my_app
        BOARD my_board
        src/main.c
)

hss_generate_vscode(my_app)
```

That writes `.vscode/tasks.json` and `.vscode/launch.json` during CMake configure.

For the shortest form, `hss_add_firmware()` also accepts `GENERATE_VSCODE`:

```cmake
hss_add_firmware(my_app
        BOARD my_board
        GENERATE_VSCODE
        src/main.c
)
```

Alternatively, configure the firmware project normally, then build the generated VS Code target:

```sh
cmake -S . -B build/debug \
  -DCMAKE_TOOLCHAIN_FILE=third_party/stm32-baremetal-framework/cmake/arm-gcc-toolchain.cmake \
  -DHSS_BOARD_PATHS=$PWD/boards \
  -DCMAKE_BUILD_TYPE=Debug
cmake --build build/debug --target vscode_my_app
```

For framework examples, the target name follows the firmware target:

```sh
cmake --build build/examples/stm32g0_minimal --target vscode_stm32g0_minimal
```

All three workflows write:

- `.vscode/tasks.json`
- `.vscode/launch.json`

Existing tasks and launch configurations are preserved. Entries generated for the same HSS target are replaced.

## Generated Tasks

The generated tasks are:

- `HSS: configure <target>`
- `HSS: build <target>`
- `HSS: flash <target>`
- `HSS: openocd <target>`
- `HSS: sync board <board>`

Flash and OpenOCD tasks call the CMake targets generated by `hss_add_firmware()`.

## Debug

The generated launch configuration is:

- `HSS: Debug <target>`

It uses Cortex-Debug with:

- the generated `.elf`
- `arm-none-eabi-gdb`
- OpenOCD
- the board's OpenOCD interface and target files
- `main` as the run-to entry point

CubeMX and the board manifest still own the low-level OpenOCD target selection.
